# G7-0 diagnosis: why the full-state path loses to the fallback on held-out sessions (post-hoc, not a rescue)

Generated by `scripts/iscx_diag.py`. Long flows (more than 50 packets), packet-level macro-F1. Model k was trained on the other fold; 'in-sample' means the flows it was trained on.

| model | evaluated on | full model | per-packet fallback |
|---|---|---|---|
| trained excluding fold 0 | held-out (fold 0) | 0.358 | 0.736 |
| trained excluding fold 0 | in-sample (fold 1) | 0.900 | 0.889 |
| trained excluding fold 1 | held-out (fold 1) | 0.366 | 0.609 |
| trained excluding fold 1 | in-sample (fold 0) | 0.940 | 0.877 |

In-sample the full-state path beats the fallback (the pipeline works: features, phase trees, emulator). On held-out session groups it collapses, while the per-packet tree, which uses TTL, ToS and window, generalises better. With 29 VPN-only captures in 16 session groups the flow-statistics trees memorise sessions. The pre-registered G7-0 rule (gap below 0.03 kills the workload) stands; the models were not tuned after seeing this. Any model change would be a new dated, post-hoc addendum.
