# Tofino-1 feasibility of two-table admission (paper analysis), 2026-09-24

Source: p4-dataplane-engineer agent. **Nothing was compiled or run; every stage count is reasoning from NetBeacon's `@pragma stage` pins, not a compile log.** Items marked UNVERIFIED are from memory.

- **Full d-left does not fit.** Splitting all 12 per-flow register arrays doubles the stateful ALUs in the pinned feature stages (25 against 13), which needs about 2 to 3 more ingress stages; NetBeacon's ingress already uses all 12.
- **A reduced variant might fit (P-b).** Split only the identity registers per way (tag packed with last-seen time in one pair register per way, plus the result); keep the eleven feature registers as single arrays indexed by the chosen slot; keep the claim write in the recirculated second pass. Stage-neutral only if one stateful ALU can do the tag compare, refresh and idle test together; otherwise +1 stage. Fallback: P-a plus moving `Pkt_Tree`/`Treatment` to egress (NetBeacon's egress is empty, `switch.p4:731, 738-743`).
- **G0's "all 12 stages" refers to the ingress chain only** (egress is empty), so kill criterion (h) may be overstated; on Tofino-1 ingress and egress share stage memory (UNVERIFIED).
- **Hazards the emulator does not model:** the way bit must be carried to the recirculated pass (e.g., in `hdr.ethernet.dst_addr`, zeroed at `switch.p4:730`); a flow can own both ways if slot state changes between its pass 1 and pass 2 (the emulator assumes instantaneous recirculation); feature tables indexed by a computed slot may hit the hash-distribution-unit constraint (class 11).
- **Keyed second polynomial:** one extra hash, no SRAM/SALU cost, probably no stage (inferred); runtime keying through `set_default_with_user_defined` is verified in the SDE 9.13.1 examples (`tna_dyn_hashing/test.py:744-756`) and unverified on 9.13.2 and for a `@symmetric` hash. Only the polynomial matters (init and final XOR are constants). Rotation remaps all live flows in that way at once (a mass downgrade); rotate one way at a time.
- **Symmetric-hash risk (affects the baseline emulation too):** a linear symmetric hash may depend only on `src⊕dst`, `sport⊕dport`, `proto` (inferred by linear algebra, not verified; `docs/g0/bos.md:105`). The emulator sorts tuples instead.
- **Cheaper variants:** V1 second choice through recirculation (0 SALU, 0 SRAM, but every packet of a refused long flow recirculates: new attack surface); V2 small controller-maintained stash table (about 2 to 4 SRAM blocks for 1,024 entries, controller latency and flooding limits).
- **Compile-only check for a human** (separate build directory, no `bf_switchd` restart) is in the agent's report and in `docs/sde_validation_request.md`; nothing was run.
